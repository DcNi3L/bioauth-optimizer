# BioAuth Optimizer

Программное средство оптимизации параметров биометрической аутентификации.
СРО2 по дисциплине «Методы и инструменты оптимизации», Университет «Туран».
Автор: **Мекенбаев Даниэль Кайратханович**, магистрант ОП «Информационные системы».

Система реализует методы из статьи СРО1 «Многокритериальная оптимизация параметров систем биометрической аутентификации»:

| Модуль            | Метод СРО1                                                                 | Результат                                                                        |
| ----------------- | -------------------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| Оптимальный порог | Минимум байесовской стоимости `E(τ) = cFA·FAR(τ) + cFR·FRR(τ)` (формула 1) | τ\* против точки равных ошибок, выигрыш в %, графики FAR/FRR/E и ROC             |
| Состав факторов   | Целочисленное программирование с правилом «И» (формулы 2–3)                | Оптимальный набор, рейтинг допустимых наборов, анализ чувствительности к бюджету |

С версии 3 BioAuth также **сервер авторизации OpenID Connect**: другие сервисы подключают биометрический вход
стандартной библиотекой OIDC (код + PKCE, refresh-токены, client credentials). Документ обнаружения —
<http://localhost:3000/.well-known/openid-configuration>, клиентов регистрирует администратор в разделе
«Администрирование → Приложения OAuth», пример — «Разработчикам → Демо-клиент OIDC» (ADR-0018).

Интерфейс устанавливается как **PWA** (кнопка «Установить приложение» в боковой панели или меню браузера) и
открывается без сети в режиме «только просмотр сохранённых страниц». Для SEO задайте публичный адрес сайта:
`RP_ORIGIN=https://bioauth.example.kz make up` — из него строятся канонические ссылки, Open Graph и `sitemap.xml`.

Модельный пример статьи воспроизводится точно и закреплён тестами: τ_EER = 0,531, τ\* = 0,5818, снижение потерь 41,8 %; 6 допустимых наборов из 31, оптимум F2+F5, при бюджете 2,0 — F1+F2.

## Запуск

```bash
make up            # или: docker compose up --build
```

Интерфейс — <http://localhost:3000>, Swagger — <http://localhost:4000/api/docs>. Поднимаются `db`, `api`, `web` и сервис
распознавания `bio-engine` (только во внутренней сети). Администратор по умолчанию — `admin` / `change-me-admin-123`
(смените через `ADMIN_PASSWORD`); при первом входе он регистрирует passkey. Других сотрудников создаёт команда
`STAFF_PASSWORD=… pnpm --filter @bioauth/api staff -- --login anna --role researcher`.

Камера и passkey работают только в безопасном контексте: на `localhost` или по HTTPS. Для демонстрации с другого
устройства нужен HTTPS (обратный прокси с сертификатом) и `RP_ID` / `RP_ORIGIN` с этим доменом.

Разработка (Node.js 22, pnpm 10):

```bash
make setup         # проверка окружения, зависимости, сборка пакетов, git-хуки
make db migrate    # PostgreSQL в Docker + миграции
make dev           # api :4000 и web :3000
make bio-setup     # Python 3.12: зависимости и модели bio-engine (проверка SHA-256)
make test-bio      # тесты bio-engine
make check         # формат, линтер, типы, тесты — то же, что CI
make help          # все команды
```

Коммиты проверяются husky: lint-staged (ESLint + Prettier) и commitlint (Conventional Commits, см. [AGENTS.md](AGENTS.md)).
