# Журнал изменений

Формат — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/), версии — [SemVer](https://semver.org/lang/ru/).
Версия вычислительного ядра `@bioauth/optimization-core` указывается отдельно: в 2.0.0 ядро не менялось (1.0.0).

## [Unreleased]

### Добавлено

- **Повторное подтверждение для опасных действий (#41, ADR-0021).** Смена роли, изменение и удаление клиента OIDC,
  утверждение и откат политики, удаление passkey сотрудником — только если второй фактор подтверждён не более 5 минут
  назад (`STEP_UP_MAX_AGE_SEC`); иначе `403 step-up-required`. Интерфейс сам показывает окно проверки (passkey, код из
  приложения или код восстановления) и повторяет запрос. Миграция `0008_step_up.sql`.
- **Озвучка команд сканера (#42).** Кнопка с динамиком в окне камеры (вход и регистрация лица) читает подсказки
  голосом браузера (Web Speech API, ru/kk/en, синтез на устройстве). Выключена по умолчанию, выбор запоминается.
  Подсказка озвучивается, только если продержалась 350 мс; та же фраза — не чаще раза в 6 с, поэтому мелькающие
  подсказки не превращаются в скороговорку. Если в системе нет казахского голоса, браузер читает голосом по умолчанию
  (об этом говорит подсказка кнопки).
- **Текст согласия v2 (#49).** Явно упоминает ритм набора, что именно хранится, срок хранения и удаление. Для
  регистрации ритма набора нужна v2 (`403`, `code: consent-outdated` при v1); принятие v2 заменяет v1 без удаления
  биометрии (`details.supersedes` в журнале). В `GET /identity/me` поле `consent.current`; в профиле — предложение
  обновить согласие. Форма согласия протокола испытаний обновлена.
- **Ротация ключа для TOTP и ритма набора (#50).** `pnpm --filter @bioauth/api rekey` перешифровывает также
  `user_totp` и `keystroke_template`; после прогона старый ключ можно удалить из `TEMPLATE_KEYS`.
- **Выгрузка журнала аудита (#43).** `GET /audit/export?format=csv|json&from=&to=&action=` (admin, auditor): записи по
  возрастанию номера, до 10 000 за запрос, в заголовках `X-Audit-Chain-OK` / `X-Audit-Chain-Events` — результат проверки
  цепочки на момент выгрузки. CSV с BOM для Excel и защитой от формул (`=`, `+`, `-`, `@`). Кнопки на странице журнала.
- **Приложение-аутентификатор (TOTP, RFC 6238).** Второй фактор сотрудника вместо passkey и запасной путь без камеры:
  `POST /mfa/totp/setup|confirm|verify`, `DELETE /mfa/totp`. SHA-1, 6 цифр, шаг 30 с, окно ±1 шаг; один и тот же
  код дважды не принимается; после 5 неверных кодов проверка блокируется на 5 минут. Секрет хранится зашифрованным
  (AES-256-GCM, AAD = пользователь). Страница «Профиль → Безопасность»: QR-код (строится в браузере), ручной ввод ключа.
- **Коды восстановления.** 10 одноразовых кодов при включении TOTP: `POST /mfa/recovery/verify|regenerate`; в базе —
  только scrypt-хэши, код гасится атомарно; показ один раз, копирование, скачивание .txt, печать.
- **Ритм набора текста (поведенческая биометрия).** `GET/POST/DELETE /keystroke…`: пять повторов фразы при регистрации,
  проверка одного ввода. Признаки — время удержания клавиш и интервалы между нажатиями; шаблон — среднее и разброс;
  расстояние — масштабированное манхэттенское с отсечкой. Шаблон шифруется AES-256-GCM и удаляется при отзыве согласия;
  5 отказов подряд — пауза 5 минут. Экран в профиле (запись, проверка, удаление). Порог подобран на синтетической
  модели (FAR ≈ 1,5 %, FRR ≈ 10 %); на людях точность ниже, фактор — дополнительный. Миграция `0007_keystroke.sql`.
- **Каталог факторов «v3.3 — факторы реализованной системы»**: лицо, passkey, TOTP, ритм набора с пометкой происхождения чисел.
- [ADR-0020](docs/adr/0020-totp-recovery-keystroke.md); справочник API: тег «Второй фактор (TOTP)» и «Динамика набора».
- Вход сотрудника: после пароля — passkey или код из приложения, ссылка «Использовать код восстановления»; способы
  `totp` и `recovery` в истории входов, `amr=otp`. Миграция `0006_mfa.sql`. Словари ru/kk/en.

## [3.2.0] — 2026-11-10

### Добавлено

- **Сканер лица: восемь команд «живости» вместо четырёх.** Новые: наклон головы к левому и правому плечу
  (`TILT_LEFT`, `TILT_RIGHT`), подбородок вниз (`CHIN_DOWN`), отдаление от камеры (`MOVE_AWAY`). Три команды сессии
  выбираются из 336 упорядоченных троек вместо 24. Для каждой команды — своя анимированная направляющая в окне камеры.
- Геометрия кадра дополнена углом наклона `rollDeg`; сильно наклонённые кадры (больше 20°) не годятся для регистрации.
- Во время проверки: кнопка «Остановить», номер шага в подсказке («Шаг 2 из 3»), короткая вибрация на телефоне,
  когда движение засчитано.
- **Справочник API** стал подробным: у каждой операции — кто имеет доступ и предел частоты (из тех же декораторов,
  что проверяет охранник), ответы об ошибках RFC 7807 с примерами, описания и группы разделов, примеры запросов
  с числами СРО1; описаны все конечные точки OpenID Connect; вводная глава — быстрый старт, способы аутентификации,
  таблица ошибок, соглашения.
- `GET /api/v1/identity/viewer` — текущий пользователь или `{ "user": null }` без ошибки 401 (для интерфейса).
- Материалы для заявки в Казпатент: `docs/deliverables/kazpatent/`, `make kazpatent-listing`.
- Перевод на казахский и английский расчётных экранов («Порог», «Состав факторов», «История») и их графиков;
  пример переменных окружения `.env.example`.

### Исправлено

- Наклон головы к плечу засчитывался как поворот: поворот и подбородок теперь считаются в системе координат лица.
- Страница «Состав факторов» на телефоне выходила за ширину экрана; таблица факторов прокручивается внутри карточки.
- В консоли браузера у посетителя без входа больше нет ошибки 401 на каждой странице.
- В примерах ответов справочника вместо границ целого типа (−9007199254740991) — обычные значения.

## [3.1.2] — 2026-11-05

### Изменено

- Справочник API — **Scalar** вместо Swagger UI (`/api/docs`, ADR-0019): поиск, примеры на нескольких языках, отправка
  запросов, светлая и тёмная темы в цветах интерфейса. Сборка Scalar раздаётся самим api — справочник работает без
  интернета; телеметрия, внешние шрифты и облачные функции отключены.
- Спецификация OpenAPI — `/api/openapi.json` (прежний `/api/docs-json` сохранён); в описании — аутентификация и
  конечные точки OpenID Connect; версия берётся из `package.json`.
- Переменная интерфейса `NEXT_PUBLIC_SWAGGER_URL` переименована в `NEXT_PUBLIC_API_DOCS_URL`; пункт «Документация API
  (Scalar)» в боковой панели.

## [3.1.1] — 2026-11-05

Аудит версии 3.

### Исправлено

- Отключённая учётная запись: вход по паролю отклоняется (403, отказ в истории входов), вход по лицу не начинается,
  refresh-токены приложений отзываются, обмен кода и userinfo отклоняются.
- Согласие на доступ приложения проходит те же проверки, что и продолжение авторизации (MFA сотрудника, `max_age`).
- RP-Initiated Logout без действительного `id_token_hint` больше не завершает сессию молча: пользователь подтверждает
  выход на странице `/oauth/logout` (защита от выхода по чужой ссылке).
- Повторённые параметры запроса авторизации и некорректный заголовок Basic возвращают ошибку OAuth вместо 500.
- Создание сотрудника с занятой почтой не оставляет учётную запись без почты.
- Интерфейс: расхождение гидратации на части страниц (скрипты из `<head>` перенесены в `next/script`), фокус в
  выезжающем меню и в выпадающих меню (стрелки, Esc), перевод сообщений об ошибках и уведомления о дрейфе, даты на
  графике входов, вход для приложения у сотрудника без passkey; service worker не сохраняет адреса с кодом авторизации.

### Документация

- docs 01, 03–08, README, ADR-0018, диаграммы 21–22; руководство пользователя, техническое описание и презентация
  обновлены под версию 3; снимки экранов `docs/deliverables/screenshots/v3`.

## [3.0.0] — 2026-11-05

Сервер авторизации, учётные записи и новая оболочка интерфейса. Ядро не менялось (1.0.0).

### Добавлено

- **Сервер авторизации OpenID Connect** (ADR-0018): обнаружение, JWKS (RS256), код авторизации + PKCE S256,
  refresh-токены с ротацией и обнаружением повторного использования, `client_credentials`, `userinfo`, интроспекция,
  отзыв, выход; экран согласия; демо-клиент `bioauth-demo` на странице «Разработчикам → Демо-клиент OIDC».
- **Учётная запись**: фото профиля (загрузка файла или снимок с камеры, обрезка до квадрата), имя и почта, активные
  сессии с устройством и IP и их завершение, история входов с отказами, подключённые приложения.
- **Админ-панель**: сводка (показатели, входы за 14 дней, способы и причины отказов), пользователи (поиск, фильтры,
  роли, отключение, снятие блокировки, завершение сессий, создание сотрудников), журнал входов, приложения OAuth
  (регистрация, ротация секрета, отключение, удаление, конечные точки).
- **Интерфейс**: боковая панель со всей навигацией (на телефоне — выезжающая), верхняя панель с языком (русский,
  казахский, английский), темой (светлая, тёмная, как в системе) и меню учётной записи; страница «Алгоритм» —
  все расчёты и пороги на одной странице с вкладками; контур головы и направляющие команд в окне камеры.
- **Тесты**: e2e API v3 (9 сценариев), Playwright — поток OIDC в браузере и переключение языка и темы.

### Изменено

- Вход по командам: команды измеряются относительно исходного положения, PAD — по фронтальным кадрам, личность —
  по сходству каждого кадра с исходным; подсказки позы в реальном времени.
- Адреса `/threshold`, `/factors`, `/experiments`, `/admin/calibration|report|batch|pad-test` перенаправляют на вкладки
  «Алгоритма».

## [2.0.0] — 2026-11-05

Живая биометрия и замкнутый контур калибровки (ТЗ — `docs/10-live-biometrics-spec.md`).

### Добавлено

- **bio-engine** (Python 3.12, FastAPI, ONNX Runtime): детекция YuNet, эмбеддинг SFace, пассивная проверка «живости»
  MiniFASNet; контроль качества кадра; проверка активных команд по геометрии 5 опорных точек; модели закреплены
  по SHA-256; пакетный режим `POST /v1/batch/face` (протокол пар с seed).
- **Пользователи и доступ**: регистрация субъекта, вход сотрудника по паролю (scrypt), сессии в httpOnly cookie,
  роли `subject` / `admin` / `researcher` / `auditor`, двухфакторный вход сотрудников с passkey, защита от CSRF,
  блокировка после неудачных попыток; команда `pnpm --filter @bioauth/api staff` для создания сотрудников.
- **Биометрия**: согласие и его отзыв с удалением данных; регистрация лица по 5 кадрам; шаблоны AES-256-GCM
  с отменяемой проекцией и ротацией ключа (`rekey`); passkey (WebAuthn, платформенный аутентификатор).
- **Вход по политике**: nonce, три случайные команды, решение по правилу «И», второй шаг passkey; версии политики
  с предложением, утверждением (четыре глаза), отклонением и откатом.
- **Замкнутый контур**: калибровка τ_face и τ_pad ядром v1 с проверкой достаточности данных (правило трёх, Уилсон);
  измеренный каталог факторов; испытание PAD (APCER/BPCER, ISO/IEC 30107-3); проверка дрейфа FRR; журнал попыток;
  пакетный режим; отчёт протокола «до/после калибровки».
- **Журнал аудита** только на добавление с цепочкой SHA-256 и проверкой целостности.
- **Интерфейс**: страницы регистрации, входа и профиля; рабочее место сотрудника «Управление» (обзор, калибровка,
  политики, попытки, испытание PAD, пакетный режим, протокол, аудит).
- **Тесты**: pytest bio-engine (в том числе на настоящих моделях), контрактные примеры api ↔ bio-engine, e2e api v2,
  Playwright с поддельной камерой Chromium и виртуальным аутентификатором WebAuthn.
- **Документация**: ADR-0016 и ADR-0017, обновлённые docs/03–07, материалы протокола испытаний (`docs/protocol`),
  техническое описание, руководство пользователя и презентация версии 2.0.0; `make images-save` / `images-load` /
  `up-offline` для запуска без интернета.

### Не вошло

- Пакетная оценка изображений отпечатков (NBIS) — отложена (ADR-0013).
- Испытание на добровольцах по протоколу §10.11 проводится отдельно.

## [1.0.0] — 2026-11-04

### Добавлено

- Вычислительное ядро: оптимальный порог по минимуму E(τ) = c_FA·FAR + c_FR·FRR (аналитически для нормальной модели
  с численной проверкой и точным перебором по своим оценкам), выбор состава факторов полным перебором и
  целочисленным программированием (HiGHS) с сертификатом оптимальности, анализ чувствительности к бюджету.
- REST API на NestJS с zod-контрактами и Swagger, PostgreSQL (Kysely, SQL-миграции), история экспериментов,
  каталоги факторов, загрузка CSV с оценками.
- Интерфейс на Next.js (FSD): порог, состав факторов, история, экспорт JSON/CSV/PNG.
- Тесты: золотые тесты статьи СРО1, эталоны SciPy, property-тесты, e2e; CI GitHub Actions; Docker Compose.
