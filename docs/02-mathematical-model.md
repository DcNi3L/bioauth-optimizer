# 02. Математическая модель и алгоритмы

Документ — главный источник правды для пакета `@bioauth/optimization-core`. Любое изменение формул сначала вносится сюда, затем в код и тесты.

Обозначения как в СРО1: s — оценка сходства, правило допуска `s ≥ τ`; G — законные пользователи (genuine), I — злоумышленники (impostor).

---

## 2.1. Задача 1. Оптимальный порог (формула (1) СРО1)

```plaintext
E(τ) = cFA · FAR(τ) + cFR · FRR(τ) → min,   cFA > 0, cFR > 0
FAR(τ) = P(s_I ≥ τ),   FRR(τ) = P(s_G < τ)
```

FAR(τ) монотонно убывает, FRR(τ) монотонно возрастает.

### 2.1.1. Параметрический режим (нормальные распределения)

s_G ~ N(μ_G, σ_G), s_I ~ N(μ_I, σ_I), требуется μ_G > μ_I, σ > 0 (σ — **стандартное отклонение**, не дисперсия; при таком прочтении воспроизводятся числа статьи).

**Вычисление вероятностей** — только через `erfc`, без `1 − Φ`, чтобы не терять точность в хвостах (FAR ~ 10⁻⁶ … 10⁻¹⁵):

```plaintext
FAR(τ) = ½ · erfc( (τ − μ_I) / (σ_I·√2) )
FRR(τ) = ½ · erfc( (μ_G − τ) / (σ_G·√2) )
```

**Точка равных ошибок — в замкнутом виде.** FAR = FRR ⇔ (τ − μ_I)/σ_I = (μ_G − τ)/σ_G:

```plaintext
τ_EER = (μ_I·σ_G + μ_G·σ_I) / (σ_G + σ_I),     EER = ½·erfc( d / √2 ),   d = (μ_G − μ_I)/(σ_G + σ_I)
```

**Оптимальный порог — аналитически.** Условие стационарности E′(τ) = −cFA·f_I(τ) + cFR·f_G(τ) = 0, после логарифмирования — квадратное уравнение `a·τ² + b·τ + c = 0`:

```plaintext
a = 1/(2σ_G²) − 1/(2σ_I²)
b = μ_I/σ_I² − μ_G/σ_G²
c = μ_G²/(2σ_G²) − μ_I²/(2σ_I²) + ln(cFA/cFR) + ln(σ_G/σ_I)
```

Знак E′(τ) совпадает со знаком −Q(τ), где Q(τ) = aτ² + bτ + c, поэтому корень — локальный минимум E, если Q′(τ) = 2aτ + b < 0. Это проверяется точно, без вычисления второй производной (которая в хвостах обращается в машинный ноль). При D < 0 корней нет и E монотонна — оптимум вырожден.

При |a| < 10⁻¹² (σ_G ≈ σ_I) уравнение линейное: τ = −c/b. Корни вычисляются численно устойчивой формулой `q = −½(b + sign(b)·√D)`, τ₁ = q/a, τ₂ = c/q.

**Алгоритм `optimizeGaussianThreshold`:**

1. Кандидаты: вещественные корни, в которых E имеет локальный минимум, плюс два предельных случая: «допускать всех» (E → cFA) и «отвергать всех» (E → cFR).
2. Если задано FAR_max: τ_min = μ_I + σ_I·√2·erfcinv(2·FAR_max); корни левее τ_min отбрасываются, τ_min добавляется в кандидаты.
3. τ\* = кандидат с минимальным E. Если победил предельный случай — результат помечается `degenerate: "acceptAll" | "rejectAll"` и UI объясняет, что при таких стоимостях порог не имеет смысла.
   Корень, который лучше вырожденного решения меньше чем на 10⁻⁹ относительно, тоже считается вырожденным. Такой τ лежит в дальнем хвосте (например, τ ≈ 2,8 при E, меньшей cFR на ~10⁻³⁹), где E плоская до машинной точности. Сообщать его как «оптимальный порог» бессмысленно, а численная проверка там не может сойтись. Случай найден property-тестом и закреплён регрессионным тестом.
4. **Независимая верификация:** сетка из 10⁴ точек на [μ_I − 10σ_I, μ_G + 10σ_G] находит грубый глобальный минимум, затем бисекция по производной E′(τ) = cFR·f_G(τ) − cFA·f_I(τ), вычисленной напрямую через плотности (без квадратного уравнения), уточняет его до машинной точности. Золотое сечение здесь не подходит: E(τ) у минимума плоская, и сравнение значений функции даёт точность лишь ~10⁻⁸. Если |τ_analytic − τ_numeric| > 10⁻⁷ — результат помечается `verification: "mismatch"`, событие логируется как ошибка. На корректном коде этого не происходит никогда; проверка нужна как страховка.
5. Δ = 1 − E(τ\*)/E(τ_EER).

### 2.1.2. Эмпирический режим (оценки из CSV)

Для конечных выборок G (n_G) и I (n_I) функция E(τ) кусочно-постоянна и меняется только в значениях оценок. Поэтому **точный** минимум ищется перебором всех различных значений, а не численной оптимизацией.

```plaintext
FAR(τ) = #{ s ∈ I : s ≥ τ } / n_I,     FRR(τ) = #{ s ∈ G : s < τ } / n_G
```

**Алгоритм `optimizeEmpiricalThreshold`**, O((n_G + n_I)·log):

1. Отсортировать G и I; T = упорядоченные уникальные значения G ∪ I, плюс +∞ («отвергать всех»).
2. Два указателя проходят T, поддерживая счётчики → FAR_k, FRR_k, E_k для каждого t_k.
3. τ\* = t*k с минимальным E_k. Решения одинаковы на всём интервале (t*{k−1}, t_k], поэтому возвращается интервал и рекомендуемый порог — его середина (устойчивее к новым данным).
4. Разрешение ничьих по E: меньший FAR (приоритет безопасности), затем меньший τ.
5. EER: k, минимизирующий |FAR_k − FRR_k|; EER = (FAR_k + FRR_k)/2.
6. Если n_I < 1/FAR_max, выдаётся предупреждение: данных недостаточно, чтобы статистически подтвердить такой FAR (правило «трёх»: нужно ≥ 3/FAR_max попыток).

## 2.2. Задача 2. Выбор состава факторов (формулы (2)–(3) СРО1)

Факторы i = 1…n, x_i ∈ {0,1}, правило «И» (злоумышленник должен пройти все включённые факторы):

```plaintext
FAR(x) = ∏ FAR_i^{x_i}                FRR(x) = 1 − ∏ (1 − FRR_i)^{x_i}
L(x)   = Σ l_i·x_i                     C(x)   = Σ c_i·x_i            P(x) = Σ_{i∈PAD} x_i

min  E(x) = cFA·FAR(x) + cFR·FRR(x)
s.t. L(x) ≤ L_max,   C(x) ≤ B,   P(x) ≥ P_min,   FAR(x) ≤ FAR_max,   Σ x_i ≥ 1
```

### 2.2.1. Вычисление в логарифмическом пространстве (обязательно)

```plaintext
logFAR(x)  = Σ x_i · ln(FAR_i)            FAR(x) = exp(logFAR)
logSurv(x) = Σ x_i · log1p(−FRR_i)        FRR(x) = −expm1(logSurv)
```

`log1p`/`expm1` сохраняют точность при малых FRR; произведение многих малых FAR не уходит в денормализованные числа.

**Сравнение с допуском (ADR-0008).** Все ограничения `≤` проверяются как `lhs ≤ rhs + ε·max(1, |rhs|)`, ε = 10⁻⁹; ограничение по FAR — в лог-форме `logFAR(x) ≤ ln(FAR_max) + ε`. Без этого набор F2+F4 (5·10⁻⁵ · 2·10⁻² = 1,0000000000000002·10⁻⁶ в IEEE 754) ошибочно отбрасывается при FAR_max = 10⁻⁶, и вместо 6 допустимых наборов получается 5. Этот случай — регрессионный тест.

### 2.2.2. Решатель A — полный перебор (`exhaustive`), n ≤ 20

Эталон точности: перебираются все 2ⁿ − 1 непустых подмножеств, E считается по точной нелинейной формуле.

- Для каждой маски метрики считаются заново, суммированием в фиксированном порядке индексов (O(n·2ⁿ), для n = 20 — менее секунды). Инкрементальные обновления (код Грея) отвергнуты: при миллионе прибавлений и вычитаний накапливается погрешность, сравнимая с допуском ε, и результат зависел бы от порядка обхода.
- Хранятся лучшие K наборов (`rankingLimit`, по умолчанию 100, максимум 1000) и счётчики; `rankingComplete = true`, если допустимых наборов не больше K.
- Порядок при равенстве E (детерминизм, NFR-5): E ↑, FAR ↑, C ↑, L ↑, затем лексикографически по кодам.

### 2.2.3. Решатель B — ЦЛП по фронту Парето с сертификатом (`ilp`), n ≤ 50

Это метод СРО1: «логарифмирование делает задачу линейной по x и сводит её к целочисленному программированию». В статье назван CP-SAT; в Node.js используется MILP-решатель **HiGHS** (WASM-сборка, пакет `highs`) в той же роли (ADR-0007).

**Точная линеаризация.** Обе ошибки набора — монотонные функции двух _линейных_ форм от x:

```plaintext
L(x) = Σ ln(FAR_i)·x_i,              FAR(x) = e^{L(x)}
Λ(x) = −Σ ln(1 − FRR_i)·x_i ≥ 0,     FRR(x) = 1 − e^{−Λ(x)}
```

В статье второе слагаемое приближалось суммой Σ FRR_i·x_i. Форма Λ даёт то же значение в первом порядке, но выражает FRR **точно**, поэтому погрешности линеаризации нет вовсе.

**Сведение к двухкритериальной задаче.** E(x) = cFA·e^{L(x)} + cFR·(1 − e^{−Λ(x)}) возрастает и по Λ, и по L. Если набор y не лучше x по обеим формам (Λ(y) ≥ Λ(x), L(y) ≥ L(x)), то E(y) ≥ E(x). Значит, оптимум лежит на **фронте Парето** по (Λ, L), и достаточно обойти этот фронт.

**Алгоритм (метод ε-ограничений с отсечениями «no-good»):**

```plaintext
best ← ∞;  L_bound ← +∞;  𝒞 ← ∅
repeat
    x̂  ← argmin Λ(x)   при ограничениях (3), L(x) ≤ L_bound, отсечениях 𝒞     // MILP 1
    если x̂ не существует → стоп: фронт пройден, best — оптимум (или задача недопустима)
    LB ← cFR·(1 − e^{−(Λ(x̂) − δ)})
    если LB ≥ best → стоп: оптимум доказан
    x̂′ ← argmin L(x)   при тех же ограничениях и Λ(x) ≤ Λ(x̂) + δ               // MILP 2: «ничьи» по Λ
    для x ∈ {x̂, x̂′}: точное E(x) по 2.2.1; если допустим — best ← min(best, E(x)); 𝒞 ← 𝒞 ∪ {x}
    если x̂′ допустим по точной проверке: L_bound ← L(x̂′)
until итераций > 2ⁿ (страховка)
```

δ = 10⁻⁹ — запас на допуски MILP; он всегда направлен в безопасную сторону: занижает LB и расширяет допустимое множество.

**Почему результат точный.**

1. Наборы с L > L_bound доминируются уже найденной точкой x̂′: у них Λ не меньше (x̂ минимизировал Λ) и L больше. Поэтому их исключение не теряет оптимум.
2. Каждый следующий шаг 1 решается на подмножестве предыдущего, поэтому Λ(x̂) не убывает. Значит, LB = cFR·(1 − e^{−Λ(x̂)}) ограничивает снизу E **всех** ещё не просмотренных наборов.
3. Отсечения 𝒞 гарантируют, что ни один набор не просматривается дважды, поэтому алгоритм конечен.

**История.** Первая версия минимизировала Σ FRR_i·x_i и останавливалась по оценке cFR·(1 − e^{−S}). Property-тесты выявили два плохих случая:

- если у факторов FRR = 0, оценка равна нулю и решатель перебирал все наборы;
- при множестве «ничьих» по S он обходил их по одной.

Обход фронта Парето устраняет оба случая. Каждый закреплён регрессионным тестом: не более 3 итераций при FRR = 0, согласие с полным перебором на тысячах случайных задач.

**Трассировка на примере статьи:**

- итерация 1: x̂ = x̂′ = F2+F5 (Λ = 0,020126), best = 0,019925, L_bound = ln(5·10⁻¹¹);
- итерация 2: при FAR ≤ 5·10⁻¹¹ остаётся F2+F4+F5 с Λ = 0,071419, LB = 0,068929 ≥ 0,019925 → стоп.

Две итерации, оптимум доказан.

**Режим `auto`:** n ≤ 20 → `exhaustive`, иначе `ilp`. В режиме `ilp` рейтинг содержит только просмотренные наборы (`rankingComplete: false`).

### 2.2.4. Активные ограничения и анализ чувствительности

- Ограничение активно в оптимуме, если его запас ≤ ε·max(1,|rhs|). Для F2+F5 активно только PAD ≥ 1; L = 650 < 1000 — неактивно, как и сказано в статье.
- **Перебор бюджета** B ∈ [B_from, B_to] с шагом h: наборы, допустимые без учёта бюджета, сортируются по E один раз; для каждого B берётся первый набор с C ≤ B. Возвращаются точки (B, E\*, набор) и точки смены оптимума с отношением E_new/E_old — «цена ужесточения бюджета» из статьи.
- Пример статьи: B ∈ [0,9; 1,6) → F2+F4; [1,6; 2,1) → F1+F2; ≥ 2,1 → F2+F5. Переход 2,5 → 2,0 увеличивает E в 0,034700/0,019925 = 1,74 раза.
