# Протокол испытаний (docs/10 §10.11)

Материалы для проведения испытаний BioAuth Optimizer на добровольцах и оформления результатов:

| Файл                                                       | Назначение                                                                        |
| ---------------------------------------------------------- | --------------------------------------------------------------------------------- |
| [01-consent-form.md](01-consent-form.md)                   | Информированное согласие участника (печатается, подписывается до сессии)          |
| [02-operator-checklist.md](02-operator-checklist.md)       | Чек-лист оператора: подготовка, проведение сессии, атаки, завершение              |
| [03-report-template.md](03-report-template.md)             | Раздел для диссертации и статьи: методика, результаты, ограничения                |
| [04-results-open-datasets.md](04-results-open-datasets.md) | Этап 1: «до/после калибровки» на открытых наборах (ORL, CMU) — готовые результаты |

Расчёты выполняет сама система: **Администрирование → Протокол** (`GET /api/v1/calibration/report`) строит таблицу
«до/после калибровки» с 95%-интервалами Уилсона, **Испытание PAD** — отчёт APCER/BPCER, **Калибровка** — эксперимент,
воспроизводимый по идентификатору. Экспорт — CSV на каждой странице и JSON эксперимента.

Перед началом форму согласия и протокол согласовывают с научным руководителем и, если этого требуют правила
университета, с этической комиссией.

**Этап 1 (без добровольцев)** уже выполним: `make calibrate` калибрует лицо и ритм набора на открытых наборах и пишет
таблицу «до/после» с интервалами Уилсона и перекрёстной проверкой в `calibration-report/`
([результаты](04-results-open-datasets.md)).

**Этап 2 (добровольцы и атаки)** — по чек-листу. После испытания `make protocol-cleanup PREFIX=<префикс логинов>`
показывает участников, а с `YES=1` отзывает их согласия: биометрия удаляется, статистика обезличивается, итог
записывается в аудит (`protocol.cleanup`).
