# Чек-лист оператора сессии

## Перед днём испытаний

- [ ] Этап 1 выполнен: `make calibrate` — таблица «до/после» на открытых наборах лежит в `calibration-report/`
      ([результаты](04-results-open-datasets.md)). Для этапа 2 откатите политику на исходную, если сравнение должно
      начинаться с порога 0,363.
- [ ] Система запущена по HTTPS (или на localhost); `/health/ready` bio-engine возвращает версии моделей.
- [ ] Действующая политика — исходная (v1, τ_face = 0,363, τ_pad = 0,5, 3 команды): **Администрирование → Политики**.
- [ ] Вход администратора выполнен двумя факторами (пароль + passkey).
- [ ] Распечатаны формы согласия, подготовлена таблица «код ↔ участник» (хранится отдельно от ноутбука).
- [ ] Для атак: принтер (цветная печать A5), телефон с ярким экраном, второй монитор или планшет для видео.
- [ ] Три условия освещения: дневной свет у окна, верхний свет, приглушённый свет (≈ 50–100 лк).

## Сессия участника (≈ 20 минут)

1. [ ] Объяснить цель, дать прочитать форму, ответить на вопросы, получить подпись. Без подписи сессия не проводится.
2. [ ] Присвоить код `pNN`, записать в таблицу соответствия.
3. [ ] **Регистрация** (`/enroll`): логин = код; согласие; лицо (3 попытки, если первая не удалась — следовать
       подсказкам); passkey не обязателен.
4. [ ] **Входы** (`/login`): 10 попыток — по 3–4 в каждом условии освещения; участник выполняет команды сам.
       Неудачные попытки не повторять «до успеха» — каждая попытка идёт в статистику FRR.
5. [ ] **Атаки** (только при отметке «да» в форме, 10 участников):
       сфотографировать участника на телефон оператора → **Администрирование → Испытание PAD** →
       «Подлинное» — 2 предъявления живого участника; затем «Атака» — по 10 предъявлений: печатное фото, фото на экране,
       видео на экране. Держать носитель на расстоянии 30–50 см, слегка наклонять.
6. [ ] Удалить фото и видео участника с телефона и монитора **при участнике**.
7. [ ] Отметить в таблице: условия, число попыток, замечания (очки, борода, головной убор).

## После сбора

- [ ] **Калибровка**: модальность «лицо» → версия модели → стоимости профиля (например, cFA = 100, cFR = 1) →
      «Рассчитать». Проверить блок «Достаточность данных»; при нехватке impostor-сравнений — пакетный режим.
- [ ] Повторить для τ_pad (модальность «живость»).
- [ ] «Предложить политику» → утверждает **другой** администратор (принцип четырёх глаз; заведите второго администратора заранее).
- [ ] **Протокол**: таблица «до/после» → «Скачать CSV»; эксперимент калибровки → JSON на странице «История».
- [ ] **Испытание PAD**: отчёт при τ_pad до и после (поле «Порог для отчёта»).
- [ ] **Аудит** → «Проверить целостность» → снимок экрана.
- [ ] Удаление данных участников: `make protocol-cleanup PREFIX=p` — проверить список участников, затем
      `make protocol-cleanup PREFIX=p YES=1` (согласия отзываются, биометрия удаляется, статистика обезличивается);
      убедиться, что в аудите есть `consent.revoked` по каждому коду и итоговая `protocol.cleanup`; уничтожить таблицу
      «код ↔ участник» в срок из формы.
