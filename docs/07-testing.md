# 07. Стратегия тестирования

Главный риск продукта — неверный расчёт. Поэтому основная часть тестов сосредоточена на ядре `optimization-core`, а не на UI.

## 7.1. Пирамида

| Уровень | Инструмент | Что проверяется | Цель |
|---|---|---|---|
| Золотые тесты ядра | Vitest | Числа статьи СРО1 (§2.3) и эталоны SciPy | 100 % проходят, допуски из §2.3 |
| Property-based | Vitest + fast-check | Инварианты и согласие решателей | 1000 случайных задач на прогон |
| Unit ядра | Vitest | Каждая функция и граничные случаи | покрытие ядра ≥ 95 % строк |
| Unit бэкенда | Jest (NestJS) | Use cases с заглушками портов | ключевые ветки |
| Интеграционные | Jest + supertest на реальном PostgreSQL (`TEST_DATABASE_URL`; в CI — сервис postgres) | Репозитории, миграции, HTTP через supertest | все эндпоинты |
| E2E | Playwright | «Пример из статьи» → правильные числа на экране | 3 сценария |
| Smoke развёртывания | GitHub Actions | `docker compose up` → `/health/ready` = 200 | при каждом PR |

## 7.2. Золотые тесты (приёмочные, из СРО1)

**G-T1 Порог, пример статьи** — все величины таблицы §2.3 с указанными допусками.

**G-T2 Порог против SciPy** — 50 заранее сгенерированных наборов (μ, σ, cFA, cFR) с эталонами `scipy.stats.norm` + `scipy.optimize`, хранятся в `fixtures/threshold-scipy.json`. Скрипт генерации `tools/generate-fixtures.py` лежит в репозитории, чтобы эталоны можно было пересоздать.

**G-T3 Хвосты** — FAR при z = 8 и 10 (≈ 6,2·10⁻¹⁶ и 7,6·10⁻²⁴) совпадает со SciPy с относительной погрешностью ≤ 10⁻¹². Проверяет, что не используется `1 − Φ`.

**G-F1 Факторы, пример статьи, B = 2,5** — 31 подмножество, 6 допустимых, рейтинг и метрики в точности как в таблице §2.3; оптимум F2+F5, E = 0,019925000500 (отн. 10⁻¹²).

**G-F2 Факторы, B = 2,0** — 3 допустимых, оптимум F1+F2, E = 0,0347000500; отношение к G-F1 = 1,7415.

**G-F3 Регрессия плавающей точки** — F2+F4 (FAR = 1·10⁻⁶) допустим при FAR_max = 10⁻⁶. Тест падает, если убрать допуск ε (ADR-0008).

**G-F4 Сертификат ЦЛП** — на примере статьи `ilp` делает ровно 2 итерации, lowerBound = 0,0246900.

**G-F5 Перебор бюджета** — точки смены оптимума 0,9 / 1,6 / 2,1 (§2.2.4).

## 7.3. Property-based тесты (fast-check)

| Свойство | Формулировка |
|---|---|
| P1 Согласие решателей | Для случайной задачи с n ≤ 12: `exhaustive.objective ≈ ilp.objective` (отн. 10⁻¹²), оба решателя одинаково определяют, есть ли допустимое решение |
| P2 Оптимальность перебора | Ни один допустимый набор из рейтинга не имеет E меньше оптимума |
| P3 Монотонность по бюджету | E*(B₁) ≥ E*(B₂) при B₁ ≤ B₂ |
| P4 Стационарность порога | В τ* (если невырожден): `|E′(τ*)| < 1e-9` и E(τ* ± 1e-4) ≥ E(τ*) |
| P5 Порог против численной проверки | `|τ_analytic − τ_numeric| < 1e-7` для случайных параметров |
| P6 EER | FAR(τ_EER) = FRR(τ_EER) с отн. погрешностью 10⁻¹² |
| P7 Эмпирический режим = параметрический в пределе | При 2·10⁵ выборках из N(μ,σ) эмпирический τ* отличается от аналитического не более чем на 0,02 (фиксированный seed), а E(τ*_emp), пересчитанное по истинным распределениям, — не более чем на 1 % выше E(τ*) |
| P8 Эмпирический оптимум точен | Перебор всех порогов «в лоб» O(n²) на малых выборках даёт тот же E*, что и алгоритм с двумя указателями |
| P9 Детерминизм | Повторный запуск даёт побайтно одинаковый JSON |

## 7.4. Граничные случаи (unit)

- σ_G = σ_I (линейное уравнение вместо квадратного).
- Экстремальные стоимости cFA/cFR = 10⁶ и 10⁻⁶ → вырожденные решения `rejectAll` / `acceptAll`.
- FAR_max делает безусловный оптимум недопустимым → τ* = τ_min.
- Перекрывающиеся / совпадающие эмпирические оценки, выборка из одного элемента, все оценки одинаковы.
- n = 1; ни одного допустимого набора (422 с диагностикой); фактор с FRR = 0; n = 20 (время < 2 с); n = 21 при `solver=exhaustive` → 413.
- CSV: BOM, разделители `;` и `,`, десятичная запятая, пустые строки, неизвестная метка → понятная ошибка с номером строки.

## 7.5. E2E-сценарии (Playwright)

1. Главная → «Порог» → «Пример из статьи СРО1» → «Рассчитать» → на экране τ* = 0,5818, Δ = 41,8 %, график построен.
2. «Состав факторов» → пример → «Рассчитать» → оптимум F2+F5, 6 строк в рейтинге; бюджет = 2,0 → F1+F2.
3. «История» → открыть последний эксперимент → результат совпадает.

## 7.6. Тестовые примеры для демонстрации на защите

Помимо примера статьи, в `examples/` кладутся:
- `scores-demo.csv`: 20 000 синтетических оценок (seed 42) из распределений статьи — демонстрация эмпирического режима;
- `catalog-10-factors.json`: расширенный каталог (добавлены радужка, вена ладони, SMS-OTP, PIN, смарт-карта) — демонстрация того, что ЦЛП работает за пределами учебного примера;
- `infeasible.json`: слишком жёсткие ограничения — демонстрация диагностики.
