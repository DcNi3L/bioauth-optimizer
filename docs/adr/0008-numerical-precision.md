# ADR-0008. Численная точность: лог-пространство, допуск ε, спецфункции @stdlib

**Статус:** Принято · **Дата:** 04.11.2026

## Контекст
При подготовке документации перебор по данным статьи с наивным сравнением `FAR <= 1e-6` дал **5** допустимых наборов вместо **6**: в IEEE 754 произведение 5·10⁻⁵ · 2·10⁻² = 1,0000000000000002·10⁻⁶ > 10⁻⁶, и набор F2+F4 ошибочно отбрасывается. Кроме того, FAR в хвостах (10⁻⁶…10⁻¹⁵) теряет точность при вычислении через `1 − Φ(z)`, а произведения многих малых вероятностей уходят в денормализованные числа.

## Решение
1. **Вероятности хвостов** — только через `erfc` (`@stdlib/math-base-special-erfc`), обратная функция — `erfcinv`. Никаких `1 − cdf`.
2. **Произведения** — в лог-пространстве: Σ ln FAR_i; FRR = −expm1(Σ log1p(−FRR_i)).
3. **Нестрогие ограничения** — `leq(lhs, rhs) := lhs ≤ rhs + ε·max(1, |rhs|)`, ε = 10⁻⁹; ограничение по FAR сравнивается в лог-форме. Строгие ограничения в модели не используются. Тот же ε передаётся в MILP (правые части умножаются на 1 + ε).
4. **Детерминированный порядок ничьих** (02 §2.2.2).
5. Вывод не округляется в ядре и API; форматирование только в UI.
6. Регрессионный тест G-F3 закрепляет случай F2+F4.

## Альтернативы
- *Десятичная арифметика (decimal.js) везде* — медленно и не решает проблему exp/log/erfc. Отклонено.
- *Собственная реализация erfc* — риск ошибок; @stdlib протестирована против эталонов. Отклонено.

## Последствия
- (+) Результаты совпадают со статьёй (рис. 2б) и с SciPy.
- (−) Значения на самой границе (в пределах 10⁻⁹ относительно) считаются допустимыми — это задокументированное и ожидаемое поведение.
