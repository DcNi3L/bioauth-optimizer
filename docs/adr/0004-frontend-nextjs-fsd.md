# ADR-0004. Фронтенд: Next.js App Router + Feature-Sliced Design

**Статус:** Принято · **Дата:** 04.11.2026

## Контекст
Интерфейс состоит из двух независимых рабочих мест (порог, факторы) с общими сущностями (фактор, эксперимент) и общими графиками. Нужна архитектура, которая не даст фичам переплетаться.

## Решение
**Feature-Sliced Design**: слои `app → pages → widgets → features → entities → shared`, импорт только вниз, доступ к слайсу только через `index.ts`. Интеграция с Next.js App Router: корневая папка `app/` содержит только маршруты (файлы `page.tsx` реэкспортируют `src/pages/*`), FSD-код лежит в `src/`, пустая корневая `pages/` с README не даёт Next.js принять `src/pages` за Pages Router.

Библиотеки: TanStack Query (серверное состояние), react-hook-form + zod (формы), **ECharts** (логарифмические оси, тысячи точек, экспорт PNG «из коробки»), Tailwind + shadcn/ui, KaTeX для формул. Страницы рендерятся на клиенте (`"use client"` на уровне pages): SEO не нужен, а SSR не даёт выгоды для интерактивных форм.

## Альтернативы
- *Плоская структура components/hooks/services*: быстро превращается в свалку. Отклонено.
- *Recharts*: слабее с лог-шкалами и большими рядами. Отклонено.
- *Vite + React SPA*: проще, но пользователь выбрал Next.js; rewrites Next.js заодно снимают вопрос CORS.

## Последствия
- (+) Фичу (например, «перебор бюджета») можно удалить или добавить, не трогая остальные.
- (+) Правила проверяются автоматически (`steiger`).
- (−) Порог входа FSD выше, чем у плоской структуры; смягчается шаблоном слайса в AGENTS.md.
