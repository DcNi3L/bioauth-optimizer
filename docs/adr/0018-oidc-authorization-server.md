# ADR-0018. BioAuth как сервер авторизации OpenID Connect

**Статус:** Принято · **Дата:** 05.11.2026

## Контекст

Биометрический вход ценен, когда им пользуются и другие сервисы организации, а не только сам BioAuth. Нужен
стандартный протокол, который понимают готовые библиотеки клиентов, без передачи им биометрии.

## Решение

1. BioAuth — провайдер **OpenID Connect** (OAuth 2.1-профиль): код авторизации с обязательным **PKCE S256** для
   публичных клиентов, refresh-токены с ротацией и обнаружением повторного использования (отзыв всей цепочки),
   `client_credentials` для конфиденциальных клиентов, `userinfo`, интроспекция (RFC 7662), отзыв (RFC 7009),
   выход по инициативе приложения, параметр `iss` в ответе (RFC 9207), документ обнаружения и JWKS.
2. Токены — JWT **RS256** (`node:crypto`, без сторонних библиотек). Закрытый ключ хранится в БД зашифрованным
   AES-256-GCM ключом, выведенным HKDF из ключа шаблонов; публичный ключ публикуется в `/oidc/jwks` по `kid`.
3. Издатель — адрес интерфейса (`RP_ORIGIN`): Next.js проксирует `/oidc/*` и `/.well-known/*` на API. Вход и согласие
   — страницы интерфейса (`/login?oauth=…`, `/oauth/consent`), поэтому работают биометрия и passkey.
4. В ID-токене `amr` (RFC 8176: `face`, `hwk`, `pwd`, `mfa`) и `acr` — приложение видит, **как** проверен
   пользователь; сама биометрия наружу не передаётся. Сотрудник без завершённого MFA считается не вошедшим.
5. Клиенты регистрирует администратор безопасности (MFA); секрет показывается один раз, хранится хэш. Согласие
   запоминается по клиенту и областям; пользователь отзывает его в профиле.

## Альтернативы

- _Готовый сервер (Keycloak, ory/hydra)_ — зрелее, но отдельная система со своей БД и входом: биометрический вход
  пришлось бы встраивать плагином. Отклонено для учебного объёма; протокол совместим, замена возможна.
- _Библиотека `oidc-provider`_ — меньше кода, но своя модель хранения и сессий параллельно существующим. Отклонено.
- _SAML_ — устаревший для новых сервисов, тяжелее для SPA и мобильных клиентов.

## Последствия

- (+) Любой сервис подключается стандартной библиотекой OIDC; демо-клиент `bioauth-demo` показывает весь поток.
- (+) e2e-тесты проверяют подпись ID-токена через JWKS, PKCE, повторное предъявление кода и ротацию refresh-токена.
- (−) Ротация ключей подписи пока ручная (новый ключ становится активным, старые остаются в JWKS).
