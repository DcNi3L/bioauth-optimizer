# ADR-0012. Распознавание лица и PAD — отдельный сервис bio-engine на Python и ONNX

**Статус:** Принято · реализовано в v2.1 · **Дата:** 04.11.2026

## Контекст

Для живой биометрии (10-live-biometrics-spec) нужны детекция лица, выравнивание, эмбеддинг и пассивная проверка «живости». Требования:

- точность, достаточная для учебного и пилотного применения;
- работа на CPU;
- лицензии, допускающие использование вне чистой науки;
- решение должно приниматься на сервере, а не в браузере (недоверенной среде).

## Решение

Отдельный контейнер **bio-engine**: Python 3.12, FastAPI, onnxruntime (CPU), OpenCV. Сервис без состояния, без доступа к БД, только во внутренней сети compose.

| Задача                              | Модель                                                        | Лицензия                                                                          |
| ----------------------------------- | ------------------------------------------------------------- | --------------------------------------------------------------------------------- |
| Детекция лица и 5 ключевых точек    | YuNet (OpenCV Zoo)                                            | MIT ([Hugging Face](https://huggingface.co/opencv/face_detection_yunet))          |
| Эмбеддинг лица                      | SFace (OpenCV Zoo)                                            | Apache-2.0 ([Hugging Face](https://huggingface.co/opencv/face_recognition_sface)) |
| Пассивная PAD                       | MiniFASNet (Silent-Face-Anti-Spoofing, Minivision), ONNX-порт | Apache-2.0 ([GitHub](https://github.com/suriAI/face-antispoof-onnx))              |
| Отпечатки (исследовательский режим) | NIST NBIS: mindtct + bozorth3                                 | Общественное достояние                                                            |

API api ↔ bio-engine — JSON по HTTP с общим секретом. В api он скрыт за портами `FaceEnginePort` и `FingerprintMatcherPort` (DIP): движок заменяем без изменения use cases. Версия каждой модели возвращается в ответе и сохраняется вместе с оценками.

## Альтернативы

- _InsightFace ArcFace (buffalo_l)_ — точнее и упомянут в статье СРО1, но предобученные модели распространяются только для некоммерческих исследований. Отклонено как вариант по умолчанию; допускается как сменный движок в исследовательском режиме.
- _Вычисление эмбеддинга в браузере_ (TensorFlow.js, onnxruntime-web) — меньше трафика и задержки, но клиент может прислать любой вектор (инъекция шаблона). Решение должно приниматься на сервере. Отклонено. В браузере остаются только подсказки по положению лица.
- _onnxruntime-node внутри NestJS_ — без нового языка, но выравнивание и предобработка изображений в Node неудобны, а инференс блокирует цикл событий без пула воркеров. Отклонено.
- _Облачные API распознавания_ — передача биометрии третьей стороне и, вероятно, за пределы РК противоречит требованиям к персональным данным. Отклонено.

## Последствия

- (+) Лицензионно чистый стек, работает офлайн на CPU, заменяемый движок.
- (+) Изоляция: тяжёлые нативные зависимости не попадают в образ api.
- (−) Четвёртый контейнер и второй язык. Это допустимо: сервис маленький и без состояния, а именно для таких задач ADR-0002 оставил Python-воркер как точку расширения.
- (−) Точность SFace ниже коммерческих движков. Компенсируется калибровкой порога на своих данных (ADR-0015).

## Реализация

Реализован в `services/bio-engine`: FastAPI, onnxruntime и OpenCV 5; модели закреплены по SHA-256 в `models.lock.json`, MiniFASNet сконвертирован собственным переносом архитектуры на PyTorch (`tools/minifasnet`). Контракт с api проверяется общими примерами в `packages/contracts/fixtures/bio-engine`.
