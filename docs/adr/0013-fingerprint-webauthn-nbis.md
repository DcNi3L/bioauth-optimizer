# ADR-0013. Отпечаток: passkey с платформенным аутентификатором и NBIS для изображений

**Статус:** Принято частично · passkey реализован, NBIS отложен · **Дата:** 04.11.2026

## Контекст

Нужно использовать реальный отпечаток пальца. Веб-приложение не имеет доступа к сканеру отпечатков через браузер. Промышленные USB-сканеры требуют драйверов и SDK производителя.

## Решение

1. **Вход — WebAuthn/passkey** с `authenticatorAttachment: "platform"` и `userVerification: "required"`: Touch ID, Windows Hello, сканер Android. Отпечаток сверяется защищённым модулем устройства. Сервер проверяет подпись, флаг UV и счётчик библиотекой **@simplewebauthn/server** (MIT), клиент — **@simplewebauthn/browser**. Это фактор F5 «Аутентификатор FIDO2» из статьи СРО1, реализованный по-настоящему.
2. **Калибровка дактилоскопического сравнителя** — исследовательский режим: изображения (наборы FVC или снимки со сканера) → NBIS mindtct (минуции) + bozorth3 (оценка) в bio-engine → CSV оценок → эмпирический оптимизатор v1.
3. **USB-сканеры** — v3: локальный агент на компьютере пользователя за портом `FingerprintScannerPort`.

## Альтернативы

- _SourceAFIS_ (Apache-2.0) — современнее NBIS, но официальные реализации — Java и .NET; в Python-контейнере это ещё одна среда исполнения. Допускается как замена в v3.
- _Только сканер через локальный агент_ — реальные оценки сходства, но требуется установка ПО у каждого пользователя. Отложено до v3.
- _Без отпечатка_ — противоречит цели показать реальную многофакторную биометрию. Отклонено.

## Последствия

- (+) Настоящий отпечаток без установки ПО, на устройствах, которые есть у большинства пользователей.
- (+) Шаблон отпечатка не покидает устройство — сильная сторона для защиты персональных данных.
- (−) WebAuthn не раскрывает оценку сходства и способ проверки: при сбое устройство может предложить PIN. FAR passkey в каталоге факторов — паспортное значение платформы (например, Apple указывает 1:50 000 для Touch ID); FRR и задержка измеряются.

## Реализация

Passkey с платформенным аутентификатором и обязательной проверкой пользователя реализован (`@simplewebauthn/server`). Пакетный режим для изображений отпечатков через NBIS (mindtct + bozorth3) не реализован: сборка NBIS из исходников в образе bio-engine ещё не проверена; пакетный режим работает для лиц (`POST /v1/batch/face`).
