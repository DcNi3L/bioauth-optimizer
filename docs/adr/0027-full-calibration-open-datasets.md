# ADR-0027. Полная калибровка на открытых наборах данных

**Статус:** Принято · **Дата:** 13.11.2026

## Контекст

Замкнутый контур калибровки (ADR-0015) работает на накопленных оценках. В новой установке их нет, и все пороги
остаются начальными: τ_face взят из примера OpenCV, τ_pad — 0,5, τ_kd — по синтетической модели. Для защиты и для
первого запуска нужна воспроизводимая калибровка «из коробки».

## Решение

1. Команда `calibrate` (`make calibrate`, `make calibrate-local`) работает в процессе API без HTTP: собирает
   контекст приложения Nest и вызывает те же службы, что и интерфейс, — пакетный режим, калибровку ядром v1,
   предложение и утверждение политики. Действия пишутся в аудит от имени администратора `--as`.
2. **Лицо** — AT&T (ORL) Database of Faces: исследовательский набор добровольцев, без публичных лиц. 360 снимков
   PGM переводятся в PNG и упаковываются в zip пакетного режима UC-9.
3. **Ритм набора** — CMU Keystroke Dynamics Benchmark. Добавлен `KeystrokeBatchService`: шаблон строится тем же
   детектором, что при входе, по 5 вводам (как при регистрации), протокол пар — по Killourhy & Maxion (2009).
4. **PAD не калибруется на снимках**: подлинное предъявление — это живая камера, а снимок набора — фото, и детектор
   PAD правильно даёт ему p_live ≈ 0. τ_pad калибруется только по испытаниям UC-8, если их не меньше 5 каждого вида.
5. Наборы скачиваются с закреплённых коммитов, проверяются по SHA-256 и кэшируются.
6. В расчёт идут только оценки текущего прогона. Повторный прогон на тех же данных даёт те же τ\* и не создаёт новую
   версию политики. Порог, отвергающий больше половины законных вводов, в политику не подставляется.

## Последствия

- Новая установка получает откалиброванный τ_face за минуту, с подтверждённым FAR.
- Ритм набора на реальных данных заметно слабее синтетической оценки (EER около 27 % против 6 %). Это отражено в
  документации и делает выбор состава факторов честнее.
- Каждый повторный прогон добавляет оценки в калибровочную выборку (источник `batch`). Это видно в сводке как рост
  числа оценок, но на пороги текущего прогона не влияет.
- ORL — старые снимки в градациях серого, поэтому после накопления собственных входов калибровку нужно повторить
  на них (страница «Алгоритм → Калибровка»).
