# ADR-0014. Защита биометрических шаблонов и данных

**Статус:** Предложено (v2) · **Дата:** 04.11.2026

## Контекст

Эмбеддинг лица — биометрические персональные данные. Его компрометацию нельзя «исправить сменой пароля». Требования:

- ISO/IEC 24745: конфиденциальность, возобновляемость, несвязываемость шаблонов;
- Закон РК № 94-V: согласие, ограничение цели, хранение в РК, удаление;
- правила финансового регулятора РК: защита от несанкционированного доступа, документирование сбора, хранения и уничтожения.

## Решение

1. **Изображения не хранятся.** Кадры обрабатываются в памяти bio-engine и отбрасываются. Исключение — испытания с отдельным согласием, только на время сессии.
2. **Шифрование шаблонов:** AES-256-GCM, уникальный IV на запись. Ключ хранится вне БД (переменная окружения, в промышленной среде — KMS или HSM). `key_id` в записи позволяет ротацию с фоновым перешифрованием.
3. **Отменяемый шаблон (опция политики):** перед сохранением эмбеддинг умножается на случайную ортогональную матрицу, порождённую секретом субъекта. Косинусное сходство сохраняется — для ортогональных преобразований сходство не меняется. При компрометации секрет меняется и шаблон перевыпускается при следующей регистрации. Разные системы с разными секретами получают несвязываемые шаблоны.
4. **Минимум данных в журналах:** в `auth_attempt` хранятся только числа (оценки, исходы, время). Логи api и bio-engine не содержат изображений и векторов (проверяется тестом NFR-B6).
5. **Жизненный цикл:** согласие с версией текста → регистрация → использование → удаление по запросу или отзыву согласия. Оценки калибровки обезличиваются. Каждый шаг пишется в журнал аудита с цепочкой хэшей.

## Альтернативы

- _Гомоморфное шифрование и сравнение в зашифрованном виде_ — сильная защита, но непропорционально сложно для v2. Отложено; тема для диссертации.
- _Хранение шаблона только на устройстве пользователя_ — для лица это потребовало бы доверять клиенту при сравнении (см. ADR-0012). Для отпечатка именно так и сделано через passkey (ADR-0013).
- _Без шифрования, только права БД_ — недостаточно против утечки резервной копии. Отклонено.

## Последствия

- (+) Утечка базы без ключа не раскрывает эмбеддинги; отменяемый шаблон даёт возобновляемость и несвязываемость.
- (−) Нужно управлять ключом. Потеря ключа означает повторную регистрацию всех субъектов — это задокументированная процедура.
