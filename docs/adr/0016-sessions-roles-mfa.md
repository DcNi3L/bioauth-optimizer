# ADR-0016. Сессии в httpOnly cookie, роли и двухфакторный вход сотрудников

**Статус:** Принято · **Дата:** 04.11.2026

## Контекст

v1 — открытый расчётный инструмент без пользователей. v2 хранит биометрию и меняет политики аутентификации, поэтому
нужны вход, разграничение прав и защита административных действий. Система — модульный монолит с веб-клиентом на том же
origin (Next.js проксирует `/api`), без внешнего провайдера удостоверений.

## Решение

1. **Сессии на сервере.** Случайный токен 256 бит в cookie `bioauth_session` (httpOnly, SameSite=Lax, Secure вне
   localhost); в БД хранится только его SHA-256 (`user_session.token_hash`), срок — `SESSION_TTL_HOURS`. Выход и
   отзыв — удаление строки.
2. **Закрыто по умолчанию.** Глобальный охранник требует сессию на всех маршрутах; открытые маршруты (весь v1, начало
   входа и регистрации) явно помечены `@Public()`.
3. **Роли:** `subject`, `admin`, `researcher`, `auditor` — проверяются декоратором `@Roles()`. Аудитор только читает,
   а оценки и логины в журнале попыток ему не показываются.
4. **MFA для изменений.** Пароль сотрудника (scrypt) — первый фактор; сессия получает `mfa_complete` только после
   passkey. Предложение, утверждение и откат политик требуют `@RequireMfa()`.
5. **CSRF.** Кроме SameSite, для изменяющих запросов проверяется заголовок `Origin` по списку `CORS_ORIGIN`.
6. **Подбор.** Ограничение частоты (`AUTH_RATE_LIMIT_PER_MIN`), блокировка пользователя после 3 неудачных
   попыток на 15 минут; для неизвестного логина создаётся «пустая» сессия входа, чтобы ответ не раскрывал, существует ли
   пользователь.
7. **Сотрудники** создаются командой `pnpm --filter @bioauth/api staff` (первый администратор — из `ADMIN_LOGIN` /
   `ADMIN_PASSWORD` при старте).

## Альтернативы

- _JWT в localStorage_ — доступен скриптам страницы (XSS), отзыв требует списка отзыва. Отклонено.
- _Внешний IdP (Keycloak, OAuth)_ — избыточен для учебной системы и усложняет развёртывание в одну команду.
- _Сессии в Redis_ — PostgreSQL уже есть, нагрузка мала (ADR-0005).

## Последствия

- (+) Токен недоступен JavaScript; кража базы не даёт действующих токенов.
- (+) Права проверяются в одном месте; новый маршрут без явной пометки закрыт.
- (−) Каждый запрос читает сессию из БД — приемлемо при учебной нагрузке; при росте можно кэшировать в памяти процесса.
