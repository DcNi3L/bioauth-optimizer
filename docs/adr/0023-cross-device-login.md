# ADR-0023. Вход на компьютере с подтверждением на телефоне (QR)

**Статус:** Принято · **Дата:** 13.11.2026

## Контекст

На компьютере без камеры и без passkey войти по политике «лицо + passkey» нельзя. При этом у человека обычно есть
телефон, на котором он уже вошёл в BioAuth по лицу или passkey. Нужен способ перенести вход с телефона на компьютер,
не вводя пароль и не раскрывая сессию телефона.

## Решение

1. `POST /cross-device`: компьютер получает запрос (срок 2 минуты), число 10–99 для сверки, секрет опроса и адрес
   `/approve?r=<id>#k=<ключ>` для QR-кода. Ключ подтверждения передаётся во фрагменте адреса: браузер не отправляет
   его на сервер и в заголовке `Referer`. В базе хранятся только sha256 секрета опроса и ключа.
2. Телефон с действующей сессией открывает адрес из QR-кода. Он видит браузер и адрес компьютера и выбирает из трёх
   чисел то, что показано на экране компьютера (`POST /cross-device/{id}/approve`). Если выбрано неверное число,
   запрос отменяется. Кнопка «Это не я» отклоняет запрос.
3. Подтверждать можно только из «свежей» сессии телефона: вход или проверка второго фактора не раньше
   `STEP_UP_MAX_AGE_SEC` (5 минут) назад. Иначе ответ — `403 reauth-required`, и страница предлагает подтвердить
   passkey этого телефона.
4. Компьютер раз в 2 секунды опрашивает `POST /cross-device/{id}/status` и после подтверждения один раз забирает
   сессию: `POST /cross-device/{id}/complete` атомарно переводит запрос `approved → consumed`. Сессия получает `amr`
   и признак завершённого двухфакторного входа от сессии телефона. Способ входа в журнале — `cross_device`.
   В журнал аудита пишутся `cross_device.approved`, `cross_device.denied` и `cross_device.completed`.

## Последствия и ограничения

- **Фишинг через QR-код.** Злоумышленник может прислать свой QR-код, и человек, подтвердив его, впустит злоумышленника.
  Сверка числа не защищает, если злоумышленник сам сообщит число жертве. Меры против этого:
  - на телефоне видны браузер и адрес компьютера;
  - явное предупреждение «подтверждайте, только если вы сами начали вход»;
  - короткий срок запроса и требование свежей проверки на телефоне;
  - запись подтверждения в журнале аудита.

  Полную защиту (проверку близости устройств, как у FIDO hybrid по Bluetooth) веб-приложение дать не может. Для входа
  с привязкой к близости следует использовать passkey с гибридным транспортом самого браузера.

- В ответе статуса нет данных пользователя: секрет опроса раскрывает только состояние запроса.
