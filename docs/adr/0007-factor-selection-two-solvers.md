# ADR-0007. Состав факторов: полный перебор + линеаризованное ЦЛП (HiGHS) с сертификатом оптимальности

**Статус:** Принято · **Дата:** 04.11.2026

## Контекст

Задача (2)–(3) СРО1 нелинейная и целочисленная. Статья предлагает: при n ≤ 15 — полный перебор; при большем n — линеаризация (логарифм FAR, сумма FRR) и решение ЦЛП (CP-SAT). Линеаризация FRR — приближение, поэтому решение ЦЛП само по себе не обязано быть точным оптимумом исходной задачи. Нужно и «использовать метод СРО1 в полной мере», и «без ошибок и точно».

## Решение

Два решателя за общим интерфейсом `FactorSelectionSolver`:

1. **`ExhaustiveSolver`** — все 2ⁿ − 1 подмножеств, метрики каждой маски считаются заново в фиксированном порядке, точная нелинейная E. Эталон, n ≤ 20.
2. **`CertifiedIlpSolver`** — метод СРО1: логарифмирование делает формы L(x) = Σ ln FAR_i·x_i и Λ(x) = −Σ ln(1 − FRR_i)·x_i линейными, причём через Λ FRR выражается точно (в статье — приближение Σ FRR_i·x_i). E монотонна по обеим формам, поэтому решатель обходит фронт Парето (Λ, L) методом ε-ограничений с отсечениями «no-good». Задачи MILP решает **HiGHS** (пакет `highs`, WASM) за портом `MilpPort`. Остановка по нижней оценке cFR·(1 − e^{−Λ}) ≥ лучшего E доказывает оптимальность (02 §2.2.3).

Режим `auto`: n ≤ 20 → перебор, иначе ЦЛП. Тесты требуют совпадения решателей (свойство P1).

## Альтернативы

- *OR-Tools CP-SAT* (как в статье) — официальных биндингов для Node.js нет; потребовался бы Python-сервис. HiGHS — открытый промышленный MILP-решатель с готовой WASM-сборкой; для задачи ≤ 50 бинарных переменных разницы в качестве нет. Отклонено для v1.
- *javascript-lp-solver* — простой, но менее надёжный branch-and-bound. Отклонено.
- *Только перебор* — точно, но не реализует метод ЦЛП из СРО1 и не масштабируется за n ≈ 25. Отклонено.
- *Только ЦЛП без сертификата (одна задача min Σ FRR_i·x_i)* — может вернуть неоптимальный набор, когда FRR велики. Отклонено.
- *Сертификат по оценке cFR·(1 − e^{−Σ FRR_i x_i})* (первая реализация) — вырождается при FRR ≈ 0 и при «ничьих»: property-тесты нашли задачи на сотни итераций. Заменён обходом фронта Парето.

## Последствия

- (+) Метод статьи реализован полностью, а результат строго оптимален для исходной нелинейной задачи.
- (+) Два независимых алгоритма проверяют друг друга в тестах.
- (−) Зависимость от WASM-модуля (≈ 2 МБ) в образе api — приемлемо.
