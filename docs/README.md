# BioAuth Optimizer — СРО2

**Программное средство оптимизации параметров биометрической аутентификации**
Задание 10 (СРО2) по дисциплине «Методы и инструменты оптимизации». Магистрант: Мекенбаев Д. К., ОП «Информационные системы», Университет «Туран».
Тема магистерской диссертации: «Разработка методов биометрической аутентификации пользователей».

## Что делает система

Система реализует два метода из статьи СРО1 «Многокритериальная оптимизация параметров систем биометрической аутентификации» — именно те, для которых в статье приведён модельный расчёт:

| №   | Задача (класс по СРО1)                   | Метод из СРО1                                                       | Что получает пользователь                                                                                       |
| --- | ---------------------------------------- | ------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| 1   | Рабочая точка сравнителя (класс 1)       | Минимум байесовской стоимости (1): `E(τ) = cFA·FAR(τ) + cFR·FRR(τ)` | Оптимальный порог τ\*, сравнение с точкой равных ошибок (EER), выигрыш в %, графики FAR/FRR/E и ROC             |
| 2   | Состав факторов аутентификации (класс 4) | Целочисленное программирование (2)–(3) с правилом «И»               | Оптимальный набор факторов, все допустимые наборы с рейтингом, активные ограничения, «цена» ужесточения бюджета |

Система обязана **точно воспроизвести модельный пример статьи** (раздел 4): τ_EER = 0,531, τ\* = 0,5818, снижение потерь на 41,8 %; 6 допустимых наборов из 31, оптимум F2+F5 (E = 0,019925), при B = 2,0 оптимум F1+F2 (E = 0,0347). Эти числа — приёмочные тесты (см. [07-testing.md](07-testing.md)).

## Стек (кратко)

Монорепозиторий pnpm + Turborepo, модульный монолит: **Next.js** (фронтенд, FSD) + **NestJS** (бэкенд, Clean/Hexagonal) + **PostgreSQL** (история экспериментов, каталоги факторов). Математика вынесена в отдельный чистый TypeScript-пакет `@bioauth/optimization-core` без зависимостей от фреймворков. Всё поднимается одной командой `docker compose up`. Redis и RabbitMQ **не используются**, обоснование и условия пересмотра — в [ADR-0005](adr/0005-storage-postgres-no-redis-rabbit.md).
